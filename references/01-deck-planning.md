# Layer 1 · Deck 级规划（宏观叙事与页间逻辑）

制作多页技术洞察 PPT 前，先完成 Deck 级规划，输出结构化大纲（章节划分、每页定位、页间逻辑关系），禁止直接跳入单页排版。

## 1. 规划输入三要素

- **受众与目标**：决策层（重趋势判断与投入方向）、技术团队（重机制拆解与可迁移方法）或评审会（重瓶颈归因与方案收益）。
- **核心总命题**：用一句话概括整套 PPT 的中心结论（例如「软件栈正从屏蔽硬件细节演进为暴露结构、物理感知、自验证闭环」）。
- **素材池**：论文 PDF、Keynote、实测数据或竞品资料，按主题聚类而非按时间/论文顺序平铺。

## 2. 四种常规叙事组织思路（Narrative Patterns）

### 模式 A：总-分-总全景型（顶会洞察 / 务虚会报告）

1. **宏观趋势导读**（1 页）：多年度热点演进 / 主题词云 + 4-5 条趋势观察。
2. **系统分层全景**（1 页）：业务负载层 / 核心发力域（红框高亮） / 硬件架构层，锚定全篇坐标。
3. **分章专题展开**（3-6 章）：每章遵循「通栏红带章节页 → 1 页旗舰/纲领工作 → 2-3 页细分对比或深化」。
4. **跨章趋势收束**（1 页）：传统共识 vs 新现实对比 + 共性规律 + 行业开放悬念 + 底部金句。

### 模式 B：问题驱动递进型（技术方案 / 架构评审）

1. **业务痛点与量化瓶颈**：真实负载约束 + 实测开销占比。
2. **既有方案失效归因**：为什么现有方法/架构走不通。
3. **核心方案与机制拆解**：按架构层或执行流拆解关键设计（①②③）。
4. **实验评估与边界分析**：主收益、消融验证、开销与适用边界。
5. **演进路线与风险清单**：短期落地动作与中长期演进方向。

### 模式 C：横向选型对比型（路线评估 / 竞品调研）

1. **问题定义与评估维度**：统一评价口径（性能、能效、改造成本、迁移门槛）。
2. **多路线同口径拆解**：每条路线用同构版式展示核心机制与实测表现。
3. **横向指标矩阵**：一页汇总关键指标与优劣势。
4. **选型结论与适用场景**：给出明确推荐及触发切换的边界条件。

### 模式 D：单点深挖精读型（组会 / 单篇或双篇论文）

- 单篇：直接采用三栏因果流（问题 → 方案 → 收益）或单页模板。
- 双篇/三篇：按「互补关系」「上下游串联」或「三维正交」合并至 1 页高密度对比。

## 3. 页间逻辑关系（显式标注与视觉承接）

在 Deck 大纲中为每一页标注与前一页的逻辑关系，并触发对应的视觉承接组件：

| 页间关系 | 含义 | 页面衔接处理 |
| --- | --- | --- |
| **总起 / 锚定** | 引出全局框架或核心发力域 | 全景图红框高亮，后续章节标题呼应全景模块名 |
| **递进 / 深化** | 上页抛出瓶颈或上层方法，下页展开底层解法 | 下页顶部加浅灰红边「承接条」（如「承接功能验证」） |
| **并列 / 正交** | 同一母题下的独立子问题（如算力/数据/空间） | 顶部加「问题定义条」，栏标题统一编号 `① ② ③` |
| **串联 / 闭环** | 上游输出作为下游输入，构成完整工程链路 | 顶部加「拟串链路条」，用 `→` 显式串起跨页/跨栏关系 |
| **收束 / 升华** | 跨页归因，提炼共性规律与落地动作 | 终页用「传统共识 → 新现实」表回扣各章编号 |

## 4. Deck 规划自检

- 任意连续两页都能说清是「递进 / 并列 / 串联 / 收束」中的哪一种，没有孤立凑数的页面。
- 每章内部有节奏变化（如 1 页单篇深度 + 1-2 页双篇/三篇横向对比），避免连续多页版式完全雷同。
- 整套报告的每一页主标题连起来读，就是一份完整的执行摘要。
