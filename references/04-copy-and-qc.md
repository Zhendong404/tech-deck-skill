# Cross-Cutting · 凝练工程文案、图文并茂与视觉自检规范

本规范贯穿 Deck 规划、Slide 规划与 Component 装配三层，确保成品达到**语言凝练、图文并茂、信息密度高、事实 100% 溯源**。

## 1. 语言凝练原则（高信噪比工程表达）

- **删净废话与过渡词**：删除「随着大模型的发展」「值得注意的是」「综上所述」「可以看出」等空话；每个词都必须承载机制、因果、约束或数字。
- **短引导词 + 压缩分句**：每条采用「**3-8 字加粗引导词** + 冒号/空格 + 精准陈述」；单条尽量控制在 45 显示字内，多个并列事实用分号 `；` 紧凑拼接。
- **平实通俗、禁用比喻**：用直白、精确的工程因果语言解释原理，让非本细分方向的工程师一眼看懂；**禁止使用比喻、拟人或文学化修辞**，避免宣传词（赋能、重塑、引领、颠覆、革命性、里程碑、极致、堪称、无疑、显著提升）。
- **无末尾句号与符号规范**：所有正文要点、表格单元格、图注末尾**不加中文句号 `。`**；中英文和数字间保留半角空格（如 `3D 堆叠`、`1.43×`、`2.82 mm²`）；统一使用 `×`、`≤`、`≥`、`→`。
- **术语保留习惯**：常用英文术语不硬译（如 `kernel`、`warp`、`tile`、`softmax`、`prefill/decode`、`cache`、`NoC`、`GEMM`、`Roofline`、`PGO`、`ISA`）；严禁将 `kernel` 译成「核/内核/注意力核/融合核」（处理器 `core` 可写「核」但勿与 `kernel` 混淆）。

## 2. 事实溯源与逻辑底线

- **核实正式论文原题**：副标题与卡片标题必须回查原文 PDF，使用正式论文标题、会议 Session 与页码，禁止用非正式别名替代原题。
- **严格因果链**：
  - **问题**：写清负载需求、量化瓶颈与既有方案失效原因，不写空泛背景。
  - **方案**：一句核心思路 + `① ② ③` 具体落地机制。
  - **收益**：必含「指标 + 幅度 + 基线 + 条件」，不写孤立相对数字。
  - **洞察启示**：不复述论文摘要，给出 1-2 条面向工程/架构/编译实践的具体判断或动作。
- **零编造**：所有数字、加速比、误差率、硬件参数均须直接来自原文；缺少证据时收窄表述，不以填满空位为由杜撰。

## 3. 图文并茂规范（配图与表格质量）

- **高信号视觉优先**：每张主卡片至少配 1 张高信息量视觉元素（原文架构/机制图、核心定量结果图、极简对比表或原生灰框流程条）；跳过封面图、纯装饰插图或低信息量概念图。
- **图文互补不重复**：图负责展现拓扑、数据流与定量曲线，文字负责讲清因果机制、约束与结论，不在正文中机械复述坐标轴。
- **300 DPI 精准裁图去原注**：从 300 DPI 渲染页按精确 bbox 裁剪，**裁掉原文自带英文图注（`Fig. X ...`）** 并去除多余白边。
- **中文结论型图注**：每张图下方配一行 `7.5-8.0 pt` `#525252` 自写图注，格式为 `Fig. X  一句话中文结论`（保留原图号便于溯源）。
- **等比缩放与对齐**：严格锁定原始宽高比，禁止拉伸变形；并排多图顶边或底边对齐。

## 4. 交付前视觉与内容自检清单

1. **视觉渲染检查**：逐页导出 PNG 目视检查，确认无文字溢出、无文本框与图片碰撞、栏间密度均衡、图上方无大块空洞留白。
2. **图文质量检查**：图片清晰无变形、无原文英文图注残留、图注编号与图一一对应、每张主卡片图文比例合理。
3. **文案凝练检查**：全文检索确认无残留中文句号 `。`（完整段落式章节副标题除外），无「注意力核/融合核/内核」误译，无口号/比喻句。
4. **卫生与溯源检查**：清除所有临时审稿高亮框（如 `#FFFF00`），核对全部论文原题、Session 页码、指标基线与页码顺延。
